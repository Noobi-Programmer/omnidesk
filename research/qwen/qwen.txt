## PHASE 1: RESEARCH & STRATEGIC DECISIONS

### 1. Product Assessment & Differentiation
OmniDesk is not a search engine wrapper; it is an **Action-Oriented Orchestration Engine**. The "Chief of Staff" metaphor holds only if the system transitions from *information retrieval* to *decision preparation*. 
*   **Weak Assumption Challenged:** Building a "Unified Priority Inbox" (P2) requires OAuth scopes, webhooks, and complex state synchronization for Gmail/WhatsApp. For a hackathon, this is a trap. It consumes 80% of the time for 20% of the demo value.
*   **Differentiation:** Our differentiator is **Verifiable Synthesis**. By leveraging TinyFish's `highlights` feature (which extracts exact verbatim substrings from source pages), we eliminate hallucinations regarding pricing, MOQs (Minimum Order Quantities), and delivery terms. If a fact isn't in the highlight, it doesn't exist in the database.

### 2. TinyFish Capability Research (Verified Facts)
I have audited the official TinyFish documentation, SDK, and cookbook patterns. Here are the technical constraints and cost realities:

*   **Search API (`client.search.query`):** 
    *   **Cost:** Free up to 12,000 requests/day. 
    *   **Capability:** Returns ranked results (`title`, `url`, `snippet`). 
    *   **Hackathon Strategy:** Use `purpose` parameter to bias results toward direct manufacturers rather than aggregators (e.g., IndiaMART).
*   **Fetch API (`client.fetch.fetch`):** 
    *   **Cost:** Free. 
    *   **Capability:** Batches up to 10 URLs. Supports CSS selector scoping and, crucially, **Highlights** (Beta). 
    *   **Hackathon Strategy:** `highlights: { query: "Extract MOQ, pricing, delivery terms", max_snippets: 5 }`. This guarantees we only process verbatim text, drastically reducing LLM token usage and hallucination risk.
*   **Agent API (`client.agent.stream`):** 
    *   **Cost:** $0.016 per step. **Not free.**
    *   **Capability:** Full browser automation via natural language goals. 
    *   **Hackathon Strategy:** **Fallback Only.** Use only if Fetch fails (e.g., 403 Forbidden/Bot Protection) or if the site is a complex SPA. We must implement a circuit breaker to prevent wallet drain.
*   **SDK:** `@tiny-fish/sdk` is the official, typed TypeScript package. We will use this exclusively.
*   **MCP:** Hosted MCP is for *development assistants* (Cursor, Claude Desktop) to control TinyFish during coding. It is **not** for our production backend.

### 3. Architecture Decisions
*   **Framework:** Next.js 15 (App Router). Server Actions and Route Handlers are sufficient. No separate backend microservices.
*   **Language:** TypeScript (Strict Mode). 
*   **UI:** Tailwind CSS + Shadcn UI. Fast, accessible, and hackathon-proven.
*   **LLM Orchestration:** **Groq API** (Free Tier). Llama 3.3 70B or 3.1 8B. Groq provides sub-second inference which is critical for streaming progress to the user.
*   **Persistence:** **Supabase (Free Tier)**. We need simple relational storage for `tasks` and `history`. It provides instant Auth and Postgres.
*   **State Management:** Server-Sent Events (SSE) for streaming research progress from the backend to the frontend.

### 4. Critical Risks & Feasibility
*   **Risk:** Supplier websites often have aggressive bot protection (Cloudflare, Akamai). 
    *   **Mitigation:** The Fetch API handles rendering, but if it fails, the UI must gracefully degrade to "Source unavailable, manual review required" rather than crashing.
*   **Risk:** LLM JSON parsing failures.
    *   **Mitigation:** Strict Zod schema validation on all LLM outputs. Retry logic (max 2 attempts) with temperature adjustment.

## PHASE 2: SYSTEM DESIGN

### 1. System Architecture Diagram

```mermaid
sequenceDiagram
    participant User as User (Frontend)
    participant API as Next.js API Route
    participant LLM as Groq (Llama 3.3)
    participant TF as TinyFish SDK
    participant DB as Supabase

    User->>API: POST /api/research (SSE)
    API->>LLM: Extract Intent & Queries
    LLM-->>API: { queries: ["packaging suppliers Bengaluru"] }
    
    loop Parallel Search
        API->>TF: search.query(...)
        TF-->>API: Raw URLs
    end
    
    API->>API: Deduplicate & Filter Aggregators
    
    loop Parallel Fetch (Batch 10)
        API->>TF: fetch.fetch(urls, highlights)
        TF-->>API: Markdown + Verbatim Highlights
    end
    
    API->>LLM: Synthesize, Rank, Draft Email (JSON Mode)
    LLM-->>API: Structured Findings & Recommendations
    
    API->>DB: Save Task Record
    API-->>User: Stream SSE Events (Progress, Findings, Draft)
```

### 2. Component Boundaries
1.  **Frontend (Workstream B):** React components, SSE client hook (`useResearchStream`), Approval UI. No business logic.
2.  **Orchestrator (Workstream A):** Next.js Route Handlers. Manages the pipeline: Intent -> Search -> Fetch -> Synthesize.
3.  **Adapters (Workstream A):** `tinyfish-adapter.ts` wraps the SDK. `llm-adapter.ts` wraps Groq.
4.  **Contracts (Workstream C):** Shared `types.ts` file defining Zod schemas.

### 3. Database Schema (Minimal MVP)
```sql
-- Supabase Migration
create table research_tasks (
  id uuid primary key default gen_random_uuid(),
  user_id uuid references auth.users not null,
  prompt text not null,
  status text check (status in ('pending', 'researching', 'synthesizing', 'completed', 'failed')) default 'pending',
  findings jsonb,
  recommendations jsonb,
  draft_email jsonb,
  sources jsonb,
  created_at timestamp with time zone default timezone('utc'::text, now())
);
```

### 4. Security & Approval Model
*   **Zero-Trust Execution:** The LLM *never* sends an email. It only generates a `mailto:` link or copies text to the clipboard.
*   **Server-Side Secrets:** `TINYFISH_API_KEY` and `GROQ_API_KEY` live in `.env.local` (backend only). Never expose to the client.
*   **Highlight Validation:** The UI will display the exact `highlights` string returned by TinyFish next to the LLM's claim. If the highlight is missing, the claim is flagged as "Unverified".

# TinyFish Integration Strategy

## Cost-Aware Pipeline
We strictly follow this sequence to maintain ₹0 budget:
1. **Search API:** `client.search.query()` (Free, 12k/day).
2. **Fetch API:** `client.fetch.fetch()` (Free). Use `highlights` for fact extraction.
3. **Agent API:** `client.agent.stream()` ($0.016/step). **Fallback only** if Fetch returns 403/Empty.

## Implementation Pattern
```typescript
import { TinyFish } from "@tiny-fish/sdk";
const tf = new TinyFish({ apiKey: process.env.TINYFISH_API_KEY! });

export async function extractData(urls: string[], goal: string) {
  const res = await tf.fetch.fetch({
    urls,
    format: "markdown",
    highlights: { query: goal, max_snippets: 3 } // Crucial for grounding
  });
  
  if (res.errors && res.errors.length > 0) {
    // Fallback to Agent API for failed URLs
    return await runAgentFallback(res.errors, goal);
  }
  return res.results;
}
```
```
